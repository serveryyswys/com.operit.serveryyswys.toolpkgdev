给AI的IDE，用于Operit插件制作

# ToolpkgDev

**给 AI 用的一整套完整 Toolpkg IDE。**

从建项目、写代码、改代码，到版本管理、编译打包，全在一个地方完成。所有操作都在一个独立的虚拟空间里进行，**碰不到你手机上的真实文件**；而且每一步都能回滚。

---

## 它能帮你做什么

### 1. 让 AI 帮你写插件，不怕改坏

AI 在这个插件里写代码时，每改一次就自动存一个快照。

- 改错了？一键回滚到上一步
- 改乱套了？回滚到昨天那个能跑的版本
- 想看看改了什么？直接看差异对比

**不会再有「AI 把项目搞崩了，从头再来」这种事。**

### 2. 项目文件不落地，安全

所有代码存在一个数据库里（`storage.db`），不散落在你的文件夹中。

- 不会误删你其他的文件
- 一个项目就是一个整体，好备份
- 需要时再导出来

### 3. 危险操作会先问你

删除整个项目、批量回滚、清空历史……这类**无法撤销**的操作，AI 不能自己动手。

它会弹一个确认框给你：

```
┌─────────────────────────────┐
│      需要你批准              │
│  该操作涉及大量不可逆操作      │
│        请谨慎选择             │
│                             │
│    【确认】    【驳回】       │
└─────────────────────────────┘
```

你点「确认」它才执行，点「驳回」就当没发生。

> 如果聊天记录太长导致按钮点不动，可以打开 **待确认操作** 页面，在那里完成确认。

### 4. 一条龙打包

写完代码不用折腾命令行：
- 自动编译 TypeScript
- 自动校验工程是否合格
- 直接产出可以安装的 `.toolpkg`

### 5. 有日志，出问题能查

插件运行时会记录每一步。出了问题不用猜，打开日志页就能看到：
- 哪个操作失败了
- 报错信息是什么
- 发生在什么时候

日志按「每一次启动」分段，可以直接复制发给作者。

## 怎么用

### 第一次用

打开 Operit 工具箱 → 找到 **ToolpkgDev** → 进入首页。

首页有几个入口：

| 入口 | 干什么 |
|---|---|
| **环境检查** | 检查你的设备能不能正常构建（缺什么会告诉你） |
| **基础配置** | 调整确认开关、危险操作阈值、快照保留数量 |
| **待确认操作** | 查看和批准那些等待你确认的危险操作 |
| **运行日志** | 看插件运行记录，排查问题 |
| **关于** | 版本信息、开源许可 |

### 建一个项目

对 AI 说：

> 帮我在 ToolpkgDev 里建一个新插件项目，叫 com.example.myplugin，用 TypeScript

AI 会自动创建。你也可以让它弹出设置表单，自己填名字和描述。

### 写代码、改代码

直接跟 AI 说你想做什么，它会自己调用工具去写。比如：

> 在 main.ts 里加一个工具，功能是读取剪贴板

AI 会：
1. 读取 `main.ts` 看现有结构
2. 用 `apply_file` 精确插入代码（不会乱改其他地方）
3. 自动存快照

### 打包

> 帮我把这个项目打成 .toolpkg

AI 会编译、校验、打包，然后告诉你产物在哪儿。

## 项目类型

建项目时要选类型，它决定了能用哪些能力：

| 类型 | 适用场景 | 能编译 TS | 能打包 |
|---|---|---|---|
| `js` | 简单 JS 脚本 | — | — |
| `ts` | TypeScript 脚本 | ✓ | — |
| `toolpkg-js` | 完整插件（JS 写） | — | ✓ |
| `toolpkg-ts` | 完整插件（TS 写） | ✓ | ✓ |

不确定选哪个？想做完整插件就选 `toolpkg-ts`。

## 数据存在哪

| 位置 | 存了什么 |
|---|---|
| `Download/Operit/@serveryyswys/devtool/` | 项目清单、配置、日志 |
| `Download/Operit/dev_package/<项目名>/` | 项目本体（代码、快照、数据库） |

这些都是**不会被自动清理**的目录，可以放心。

## 常见问题

**Q：AI 改坏了怎么办？**

让它回滚。说「回滚到上一步」或「回滚到最后一次能跑的版本」。

**Q：能导出成普通文件吗？**

能。让 AI 导出，或者用「导出」功能写到项目的 `opt/` 目录里。

**Q：为什么有些操作要确认？**

因为那些操作做了就回不来了。确认框是保护你，不是找麻烦。

**Q：日志太长了怎么办？**

日志页可以按「第几轮」筛选，只看某一次的记录。也可以点复制，整段发给作者。

**Q：环境检查报错怎么办？**

按提示来。最常见的是缺工具链：如果需要编译 TypeScript，得先装 `tsc`。
